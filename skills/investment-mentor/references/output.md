# 输出结构与三档要求

本文件是唯一的正式输出要求，恢复v0.3“报告信息＋三层报告”，并明确简/详/全面的压缩边界。章节名称、顺序、必填内容和表格按本文件执行，不得静默省略必备内容；任务模块定义分析内容，不能另造一套目录。[结构字段源](output-schema.json)仅供维护与可选检查，用户报告不用JSON。

## 适用范围与优先关系

完整项目投资价值分析、项目初筛采用项目目录。用户明确只做尽调、估值条款、IC或投后退出专项时，第二层采用下述相应专项目录；报告信息、第一层、第三层保持相同档位规则。不得为了避开完整项目要求自行改称专项。

用户明确模板或自定义结构优先，说明必要映射与未覆盖内容；没有明确要求就不得自行改名、调序、合并或省略。简/详/全面首次未选时询问一次，沿用既有偏好；直接交付且无法交互时默认详细版。

单项短问、单段修改和澄清阶段不生成正式三层报告：直接答复，再给必要依据/算式、对原判断的修正及待确认事项。用户明确一句话就一句话；不得称其为已完成完整报告。影响主体/事实/参数的关键问题未答时，先询问并交可支持部分，暂停相应结论，不能用空模板冒充交付。

## 固定外层

正式报告按以下顺序保留四个一级标题；Word/HTML等对应同等层级，Markdown使用一级标题。不把三层揉成无目录长文。

```
# 报告信息
# 一、投资判断简报
# 二、结构化项目画像
# 三、专家附录
```

报告信息保留以下六个加粗字段，简短写明，不构造机器元数据头。缺失写“未提供/待确认”，联网状态按实际，日期未知不猜。

1. 项目及拟投主体
2. 任务与研究范围
3. 分析截止日与材料期间
4. 本轮核验日期与联网状态
5. 输出档位与技能版本
6. 实际覆盖范围与主要限制

报告信息使用“**字段名：**内容”逐行填写六字段，不改成元数据表。

模型身份、推理模式、工具版本和逐调用轨迹只在测试/审计请求中附于第三层，未知如实记录；不把模型自报当宿主证明。报告信息不能作为投资依据。

## 三档的明确区别

| 项目 | 简版 | 详细版 | 全面版 |
|---|---|---|---|
| 阅读目的 | 快速判断下一动作 | 团队讨论、专项尽调准备 | 完整研究、审议准备及复评底稿 |
| 第一层 | 固定六字段，约200—350字 | 固定六字段，约400—700字 | 固定六字段，仍控制在约400—700字 |
| 项目第二层 | 固定5节，按明确映射压缩 | 固定15节，不合并省略 | 同一15节，增加证据、情景及依赖分析 |
| 9视角 | 聚焦影响当前动作的判断，不强列9行 | 9行总览＋重点3个展开 | 9行总览＋重点3个深入展开，补交叉影响 |
| 12维 | 扫描后只展示关键结果与缺口 | 12行画像＋关键维度展开 | 12行画像＋证据、因果约束和敏感性展开 |
| DP五层 | 说明关键支持、反方与验证边界 | 对最影响判断的价值点展示五层实际状态 | 对全部决定性价值点/假设展示五层实际状态 |
| 财务与估值 | 有据才算必要数值，缺参保留变量 | 给来源、公式、口径、现金及价格约束 | 参数有据时给基准/下行/上行及稀释退出；不足给情景框架与问题 |
| 第三层 | 固定3节简短追溯 | 固定9节，关键记录可核对 | 固定9节，扩充证据、计算、冲突与验证安排 |

篇幅是阅读预算，不是凑字目标：简版通常正文约1000—1800字，详细约3500—6500字，全面按任务通常6500—10000字，附录另计。用户篇幅要求优先；关键依据、限制和必备字段优先于字数建议。需要超出时解释原因，不为凑长度补事实，不为变短删条件。

## 第一层：六字段固定

使用以下六个加粗字段，按顺序各写一段完整中文；不要把同样内容再列一份“核心结论”。

1. 企业定义
2. 当前价值成长阶段
3. 当前投资倾向
4. 当前资本价值点
5. 当前核心风险
6. 下一阶段关键证据

- 企业定义：说明拟投主体、具体产品/服务、客户及收入方式，不能复制宣传语。
- 当前价值成长阶段：按产品/收入模式说明可确认状态与不能确认部分；融资轮次不等于经营阶段。
- 当前投资倾向：用现有行动口径给当前建议，分别说明公司潜力、继续跟进价值、价格下股东回报；不以一个评级替代三者。
- 当前资本价值点：优先讲有证据支持的价值，未核内容明确叫价值线索/待验证假设；没有已确认价值就直说。
- 当前核心风险：只列最可能改变判断的风险、已证否决条件或疑似待核项，未知不写成已触底线。
- 下一阶段关键证据：说明哪项资料会改变哪项判断，给下一动作及待用户答复/恢复条件。

## 第二层：简版项目目录

五个二级标题固定如下。每节至少有完整的判断句和必要依据；可用简表，但不能全是标签。

1. 业务与关键价值
2. 关键验证与反方
3. 财务、现金与条件估值
4. 风险与重新定价状态
5. 待确认问题与下一动作

v0.3栏目压缩映射固定：第1节覆盖原1—2；第2节覆盖原3—8及10—11的关键结果；第3节覆盖原12并补财务现金；第4节覆盖原9和13；第5节覆盖原14。压缩展示不等于可以忽略决定性反证、财务或价格缺参。

第2节必须讲清最关键价值的支持、反方及当前边界；第3节区分实绩/预测/假设，缺参说明停算项；第4节明确CI状态，并保留三级标题“ESG情况与投资影响”，用完整中文交代环境（E）、社会（S）、治理（G）的当前状态/缺口、重要影响和动作；第5节给具体问题、所需证据、影响与恢复条件。证据和计算细节放第三层，不复写长报告。

## 第二层：详细与全面项目目录

十五个二级标题固定如下，必须按序出现，不能以“前文已讲”删除栏目。

1. 企业定义与当前阶段
2. 当前资本价值点与支撑条件
3. 9个投资人视角总览
4. 本案重点3个投资人视角展开
5. 结构化资本画像（12个认知维度）
6. 当前关键认知维度展开
7. DP五层纵向验证结果
8. 当前验证状态与关键未验证项
9. ESG情况与投资影响
10. 当前核心风险与否决条件
11. 核心正方投资假设
12. 核心反方否定路径
13. 条件估值框架
14. 当前潜在重新定价方向
15. 下一阶段关键验证问题

| 节次 | 必填实质内容 |
|---|---|
| 1 | 法律主体/业务范围、客户和收入模式；按产品区分已知阶段/待确认，不把集团与拟投业务混同 |
| 2 | 价值是什么、为谁创造经济价值、证据与成立条件、主要反证；主张与已形成价值分开 |
| 3 | 9行视角总览，每行有当前判断、依据及对动作的影响/缺口 |
| 4 | 按影响选择重点3个，用连贯段落解释为何关键、证据与反方、如何改变判断；若仅识别1—2个有依据重点，明确数量及原因，不虚构第三个 |
| 5 | 12行认知维度画像，完整保留维度名；缺证写待核及影响，不能空格/统一勾选通过 |
| 6 | 对实际改变判断的维度解释因果机制、瓶颈和依赖；与第4节引用衔接，不重复抄写 |
| 7 | 价值点逐项五层实际状态；未执行/缺证/不适用写原因与下一证据，表格出现不代表验证通过 |
| 8 | 已核验、企业主张、线索、预测、推断和未知的关键边界；未决冲突及影响 |
| 9 | ESG六子节：范围/标准、E、S、G、重要事项与投资影响、补证整改；按活动选行业，风险与证据分开，缺证不写合规；现金及交易影响有据才算 |
| 10 | 风险信号、证据、替代解释、财务/交易影响、缓释与暂停/停止条件；区分疑似与已证否决 |
| 11 | 最强正方假设、事实支撑、必要条件、使其可成立的新证据；不只写“空间大” |
| 12 | 最强反方路径、证据与反证、影响及何种材料可推翻它；不以远期愿景抵消 |
| 13 | 财务/利润质量、现金桥与资金需求、估值对象/方法/参数、股权与条款、稀释/退出回报；不能算的给变量与问题，真实数据和合成情景分开 |
| 14 | 四种CI状态选一个及理由；有条件假设才展开共识、分歧、催化/失效与价格是否反映；不适用也保留标题和原因 |
| 15 | 问题按影响与可验证性排序，列所需证据、建议动作、暂停项与恢复条件，不预设理想答案 |

详细与全面的第3、5、7、15节分别使用以下表头。数值和条件必须在附近解释；每张重要表格配一句说明其含义及局限。除这些表与证据表外，不要求全篇表格化。

- 9视角：投资人视角｜当前判断｜主要依据｜影响及缺口
- 12维：认知维度｜可确认状态｜依据｜缺口及影响
- 五层验证：价值点｜验证层级｜当前核验结果｜未核事项与下一证据
- 问题与补证：优先级｜需确认的问题｜所需证据｜影响与恢复条件

9视角完整名单：真问题、真客户、真解法、真商业化、真复制性、真壁垒、真团队与组织、真资本路径、真底线风险。

12维完整名单：创始人与组织、市场与时机、客户与需求、产品与交付、技术与能力、商业化与收入质量、财务与资本效率、竞争与护城河、产业与生态位置、法务与治理、资本路径与退出、长期演化空间。

五层完整名单：事实层、结构层、机制层、资本层、演化层。每个进入该表的价值点必须有五层状态，不能把多个层级合成一行。第一列可重复完整名称，或用“同上/同前”明确承接上一行同一对象；新对象起始须给完整名称，不混用未说明的简称。层级名称不能改造。没有可核对的具体价值对象时，第7节写清已知/缺口/影响/所需证据，暂不制造五层结果。全面版须覆盖所有决定性假设，逐项核正方、反方、权利/许可及资金约束；不能只列正向线索。资本层可记录现金与权利传导的未知，不因无报价整体判不适用。

详细版为每个重点视角提供“判断—依据—反方/条件—动作”的连贯解释。全面版进一步比较替代解释、关键参数敏感性、产品/客户/主体间依赖及资金/退出约束；未做现场、客户或法律程序就明确未做，不能把篇幅当核验深度。

## ESG章节的必备内容

详细/全面完整项目第9节必须按序保留以下六个三级标题，不能用总体“不适用/资料不足”跳过E/S/G；每个子节有完整中文说明，缺证按已知、缺口、影响、所需证据表达。行业内容遵守[ESG模块](esg.md)，不用标签或统一评分替代依据。

1. 分析范围与适用要求
2. 环境情况（E）
3. 社会情况（S）
4. 治理情况（G）
5. 重要事项与投资影响
6. 补证、整改与跟进安排

重要事项可采用“议题｜适用要求及依据｜当前情况与证据｜判断及投资影响｜缺口与动作”表；资料少时可用段落，但不能省略适用依据、证据边界、影响及行动。简版ESG通常约200—350字，详细约500—900字；全面在同样六项中展开决定性证据、场所/价值链、整改、财务情景和交易/投后安排。篇幅不是凑字要求，证据不足只给验证方案。

第一层核心风险和下一证据须提炼重要ESG事项；第10节汇集核心风险但不重复全文，第13节引用有依据的现金影响，第15节列具体追问与恢复条件。环境社会效益、企业现金和股东回报分开；有成本已入模型就不得重复扣减。

## 明确专项任务的第二层目录

以下是用户只要求单项工作时允许的固定切换，均保留报告信息、第一层六字段和该档第三层。简版压缩每节文字，详细/全面增加证据与模型深度；不套15节空栏目。用户同时要求完整投资价值判断时，仍采用项目目录，在对应章节纳入专项结果。

**尽调专项**

1. 尽调范围与待核命题
2. 商业、技术与客户验证
3. 财务、主体与权属验证
4. 冲突、风险与结论边界
5. 补证安排与恢复条件

**估值与条款专项**

1. 估值对象与输入口径

**投委会专项**

1. 审议事项与交易方案
2. 投资逻辑及证据
3. 反方、风险与基金适配
4. 情景收益与交易保护
5. 前置条件与待决事项

**投后与退出专项**

1. 原始基准与本期变化
2. 经营与资金里程碑
3. 预警、风险与权利判断

5. 跟进行动与复评安排

## 第三层：简版固定目录

1. 关键来源与证据边界
2. 计算、假设与未核事项
3. 实际完成范围与待补检查

第1节列能追溯关键结论的来源/位置、时间及支持边界；第2节列必要原数、公式、假设或停止项，无计算写原因；第3节说明实际读取/查询/计算范围、失败/未完成项。可用紧凑编号来源，不堆技术日志，不只写“已复核”。

1. 关键证据来源
2. 关键判断依据与推导
3. 证据等级与使用边界
4. 关键未验证假设
5. 关键反方与否定路径
6. 下一阶段尽调方向
7. 实际核验与计算记录
8. 规则遵循与未完成检查
9. 输出完整性与剩余限制

| 节次 | 必填内容 |
|---|---|
| 1 | 证据表：证据ID｜命题及状态｜来源与位置｜发布或数据日期｜核验日期｜支持范围与局限；日期未知写未知，同源与范围保留 |
| 2 | 对关键结论列依据、假设、必要算式与可被推翻条件；只给可检查判断依据，不展示内部思维过程 |
| 3 | 哪些命题可用于何种结论，哪些仅自述/线索；不能用EL标签代替证据 |
| 4 | 未验证假设、所缺凭证、影响与恢复条件；不是把假设换名称当事实 |
| 5 | 回指正文第12节的主要否定路径，补其证据位置和未完成验证；避免整段重复 |

| 7 | 实际完成的本地读取、公开核验、计算与失败/未做程序；与宿主日志可核程度分开 |
| 8 | 实际检查过的来源/算术/判断/停止/一致性/任务项及修正，未完成项及影响；不写无依据Passed |
| 9 | 本档必备内容是否实质覆盖、剩余限制/待答问题、结论可用范围；结构完整不等于事实真实或获批 |

全面版在同一9节中给更完整的证据索引、参数计算/情景、冲突、实际执行范围与专项计划；详细版给关键项即可。附录不能把决定性风险、核心五层验证或停止结论藏到正文之外。

## 缺项、不适用与交付检查

保留每个必备标题。资料不足时写四项：已知、缺口、影响、所需证据；待答问题和恢复条件可融入后两项。不适用写“本节不适用”，同时说明已知任务范围、为何不适用、影响及是否还需证据。不能留空、只写TODO/待核、用0代未知，或把统一免责声明复制到全部栏目。

已在前文出现的事实可用一句具体判断和来源/章节回指，再写本节新增含义，不允许只有“同上/见前文”。修正时同步依赖结论；补齐相关缺项后停止，不反复重新生成全文。核验不足应暂停依赖判断，不能为补齐结构或字数制造事实、估值、门槛、客户或工具动作。

交付前按所选任务和档位检查：标题顺序、六字段、必备表行/字段、实质内容、计算/证据、未完成项、全文一致性及[人读语言](writing.md)。可选[结构检查器](../scripts/check_output.py)仅检查Markdown层级/字段/表格及部分空内容，不判事实、依据、语言通顺或投资价值；没有Python也必须人工完成这些检查。标题齐全和自评通过均不构成质量验收。
